# Prompt improver: frozen contracts (wave 0)

Source of truth for A-E. Code stubs: `backend/gamedevworkstation/features/{pi_contracts,pi_research,prompt_improver}.py` (paths below are relative to `backend/gamedevworkstation/`). Models in `pi_contracts.py` are final and tested to import; if wrong, report, do not diverge. All models: `extra="forbid"`, strings stripped.

## 1. Models (`features/pi_contracts.py`)

- `Fact`: `value` str ≤400; `source` str ≤300 (project-relative path, `console`, `task:<code>`, `campaign:<file>` or `unknown`; absolute or `..` rejected; `value=="unknown"` forces source `unknown`); `collected_at` ISO-8601 UTC.
- `ProjectFacts`: `schema_version=1`, `collector_version`, `project` (canonical path), `fingerprint` (sha256 of static sources), `unity_version: Fact`, `packages: dict[str, Fact]` (≤60), `render_pipeline: Fact` (the ACTIVE pipeline, not merely installed), `input_handler: Fact` (`old|new|both|unknown`), `build_scenes` ≤40, `candidates` ≤20, `git` ≤10, `docs` ≤12, `task` ≤8, `campaign` ≤8, `console` ≤8 (each `list[Fact]`), `truncated: bool`. Unknowns are `Fact(value="unknown")`, never guessed. `task`, `campaign`, `console` are refreshed every turn; the rest is cached.
- `Option`: `id` (`^[a-z0-9][a-z0-9_-]{0,39}$`, stable), `label` ≤80, `detail` ≤240, `cited_fact` ≤300 or None.
- `Question`: `id`, `topic` in `TOPICS` (`target, platform_input, acceptance, feel, assets, performance, multiplayer, bug_replay`), `text` ≤300, `options` 2-4 (unique ids), `recommended` (an option id), `rationale` ≤300, `allow_free_text=True`.
- `Answer`: `question_id`, `option_id|None`, `free_text` ≤1000, `skipped`, `answered_at`. Skipped carries no choice; otherwise option or text required. A skipped optional question becomes an explicit assumption.
- `TaskCard` (`schema_version=1`, the plan table): Identity `session_id, message_id, run_id, task_code, task_link, facts_fingerprint, citations` (≤20; service fills them); Intent `goal` (1-500), `scope` ≤20, `out_of_scope` ≤10; Acceptance `acceptance_criteria` ≤8 of `AcceptanceCriterion{id ^AC\d{1,2}$, expected ≤300, verification compile|editmode_test|playmode_test|play_signal|screenshot|replay|manual, reference, target: float|None, unit}`; Quality `quality_ladder_level` L1-L4|manual, `quality_rationale`, `backlog_story`; Resources `effort` none|low|medium|high, `budget: Budget{usd_estimate, usd_cap, max_tokens, max_calls, billing_basis api|subscription|unknown, uncertainty}`; Decisions `answers` ≤3, `assumptions` ≤8, `risks` ≤8, `blockers` ≤5; Route `route: Routing{skills ≤3, unity_route mcp|cli|none|unknown, harness builtin|claude_code|unchanged, reasons ≤4}`.
- `EvalResult`: `decision` `PROCEED|ASK`, `cited_facts` ≤20, `questions` ≤3, `task_card`, `routing`, `assumptions` ≤8. PROCEED with questions, ASK without, or duplicate question ids are invalid.
- `ImproverOutcome`: `status` `proceeded|asked|bypassed|unavailable|paused`, `reason` (bypass or failure code), `context_text` ≤6000 (appended to this turn's request only; "" when none), `execution_text` (the text to execute, `*` stripped; "" = use stored text), `message_id`, `run_id`, `item_ids`, `task_code|None`, `questions_asked`, `calls`, `estimated_tokens`. `asked` = questions were shown and answered; the context then carries the answers.
- `parse_eval(text) -> EvalResult`: accepts one JSON object with an optional code fence; raises `PiFormatError(ValueError)` for empty, non-JSON, non-object or schema failure (never partial). Constants: `SCHEMA_VERSION=1`, `TEMPLATE_VERSION="pi-eval-1"`, `COLLECTOR_VERSION="pi-facts-1"`, `MAX_QUESTIONS=3`.

## 2. Eligibility (`features/prompt_improver.py`)

```python
def check_eligibility(app, session: dict, message) -> tuple[bool, str, str]  # (eligible, reason, execution_text)
```
`message` is the stored user `Message`; evaluate its ORIGINAL text before skill expansion. Order and reason codes (`BYPASS_REASONS`); eligible returns `(True, "ok", text)`:

1. `empty` no text; `disabled` `[prompt_improver] enabled` false; `chat_only` session has no folder; `not_unity` folder lacks `ProjectSettings/ProjectVersion.txt` (use `unity_bridge.is_unity_project`); `unsupported_harness` harness not in `SUPPORTED_HARNESSES`; `harness_disabled` its `builtin_enabled`/`claude_code_enabled` false.
2. Server-recorded origin: `message.meta["origin"]` (set server-side on submit; absent = interactive user). Non-user values map to a same-named reason: `scheduled, campaign, fleet, subagent, skill_load, tool_result, recap, central_doc, handoff, harness_generated`. Compatibility checks when `origin` is absent: session `settings.scheduled_task` -> `scheduled`; campaign brief/continuation metadata -> `campaign`; `meta.tool_results` -> `tool_result`; `meta.invoked_skill` skill-load -> `skill_load`. Never infer origin from prose.
3. First non-whitespace char: a single `*` not followed by another `*` (`**` is Markdown bold and stays eligible) -> `(False, "star_prefix", text with exactly that one `*` removed)` (stored transcript unchanged; harness executes the stripped copy); `/` -> `slash_prefix`; `#` -> `hash_prefix`.
4. GDH commands (`/task`, `/workflow`, `/skill`, `/clear`, ...) are caught by `/`; also bare `gdh_command` when the server routed the text to a command handler (`meta.origin=="command"`).
Bypass returns `execution_text=text` (stripped only for `*`). Cheap, no I/O, runs before research or inference.

## 3. Module interfaces

**`features/pi_research.py`**: `EVAL_TEMPLATE` (plan text verbatim), `QUESTION_BANK: dict[topic -> (question, option basis)]`, `collect_facts(project: Path, session: dict, app) -> ProjectFacts` (blocking; callers use `asyncio.to_thread`; static facts cached by canonical project + source content hashes + `COLLECTOR_VERSION`, deletion invalidates; bounded scans/file sizes, generated dirs and escaping symlinks excluded; read-only; no Editor launch), `render_facts(facts, budget_tokens=1024) -> str` (untrusted text wrapped with `wrap_untrusted`; drops lowest-priority lists first, sets nothing in facts), `clear_cache(project=None)`.

**`features/prompt_improver.py`**: `DEFAULTS`, `APPROVAL_KIND`, `FEATURE="prompt_improver"`; `PromptImprover(app)` with
- `async improve(session, message) -> ImproverOutcome` (built-in; never raises, failure -> `unavailable` and a visible notice message `meta.notice="prompt_improver"`);
- `async improve_cc(session, message, helper: Callable[[str], Awaitable[str|None]]) -> ImproverOutcome` (`helper(prompt)` sends one tool-less text-only quiet step and returns reply text or None; coordinator owns checks, parse, cards, persistence);
- `register(app, api, S)`: `POST /api/sessions/{sid}/prompt-improver/{item_id}/save` (validates session/item ownership; idempotent `TaskBoard.create(actor=ME, session_id=sid, link_session=True, description=<rendered card>)`; returns `{"task_code","task_link","created":bool}`; does not change mode or start execution) and `GET /api/sessions/{sid}/prompt-improver/latest` (`{"outcome": ImproverOutcome-like dict | null, "card": TaskCard | null, "item_id": str|null, "task_code": str|null}`).
- The coordinator is registered as `app.extensions["prompt_improver"]`; add `"prompt_improver"` to `routes.py::_feature_modules` (owner B, in the integrator wave; wave 0 did not touch it).

Policy per plan decisions: always persist the card as an indexed item (`items.add(kind="file", subtype="prompt_improver", meta.pi="card"|"evaluation"|"failure" (card meta carries `answers`), source="prompt_improver", session_id, message_id, meta={run_id, model, template_version, collector_version})`); auto-create a Backlog task (`TaskBoard.create`) only if at least one question was answered; attached existing task -> `TaskBoard.comment` proposal, never overwrite; Plan-only or disabled board tools -> draft only. Per-session `asyncio.Lock`; idempotency key `pi:<session>:<message>` stored in KV together with the task link in one DB transaction. Calls: `check_effort(effort, token, run_id)` immediately before every dispatch (retries included), `app.usage.check(sid, run_id)`, `app.usage.record(..., feature="prompt_improver", role="assistant", run_id="pi:<sid>:<mid>")`. At most `max_calls` calls (one evaluation + at most one synthesis).

**Hook points (no mutation of stored messages)**
- `agent/loop.py::_loop`: after `pre_turn` and `migrate_project_dir`, after the non-builtin `h.run` early return, after `effort` resolves and `ctx` is built, before the `for _ in range(MAX_MAIN_TURNS)` loop (~line 280). Select the newest un-satisfied user message by id (`model_history`), call `await improver.improve(session, msg)`, `session = app.store.get(sid)` again afterwards. Inside the loop, right after `history = self.model_history(sid)` (~line 303) and before compaction/`policy.filter_messages`: call helper `inject(history, msg_id, outcome.context_text)` that returns a COPY of `history` where that message is replaced by a clone whose last text block has `"\n\n" + context_text` appended, and use `outcome.execution_text` for the `*` case the same way. Later tool rounds reuse `outcome`. Store holds the original.
- `features/claude_code.py::run_turn`: after the login/billing/effort/resume/`_ensure` steps and `proc.turn = turn`, immediately before `prompt, last_id = self._prompt(...)` (~line 916). Call `await improver.improve_cc(s, msg, helper)` with `helper` bound to a separate helper conversation (own Proc, own ids/totals/cursor, all tools denied). Then `_prompt` gets an optional `extra: str = ""` and `text_override: str|None` argument: it appends `"\n\n"+extra` to the outbound string, or as a trailing `TextBlock` in `_user_content` blocks, keeping attachments, recap and `claude_code_sent` (`last_id` unchanged).

**Approval card** kind `prompt_improver_question`, via `approvals.ask(sid, kind, payload)`. Payload: `{"subject": str (<=80, "Prompt improver: <topic>"), "markdown": str (question, option detail lines, rationale), "buttons": [{"id": option_id, "label", "decision": "approve", "style": "primary" for the recommended else "ghost"}, {"id": "skip", "label": "Skip (assume)", "decision": "deny", "style": "ghost"}], "note": {"label": "Or type an answer", "placeholder": "Optional"} (only if allow_free_text), "meta": {"run_id", "message_id", "question_id", "index": 1..n, "total": n, "topic"}}`. Answer: `{"status": "approved"|"denied", "choice": option_id, "note": str}`; `approved` with `note` and no choice is free text (a typed note wins over `choice`). `denied` on a critical question -> `paused`; on an optional one -> assumption. `timed_out`/expired after restart -> never inferred; re-ask or pause. This kind is separate from `claude_code_question` (cap four) and capped at `max_questions`.

**Config `[prompt_improver]`** (add to `default_config.toml`, `Config.prompt_improver: dict`, `TYPED_SECTIONS`, `settings_routes.EDITABLE` and `NO_PROVIDER_RESET`): `enabled=true, max_questions=3, model="claude.fast", effort="low", builtin_enabled=true, claude_code_enabled=true, max_calls=2, max_input_tokens=4096, max_output_tokens=2048, timeout_s=30, budget_usd=0.03, breaker_failures=2, breaker_pause_s=600` (circuit breaker: after `breaker_failures` consecutive outage-type failures in a session, or for the same model, the improver is skipped with reason `cooling_down` for `breaker_pause_s`, one notice "Prompt improver paused for 10 minutes after repeated failures."; a success resets it; positive ints, validated like `timeout_s`). Validation on load and PATCH (HTTP 400 on PATCH): booleans are bool; `model` non-empty str resolving via `config.resolve` (Claude helper: only a model that login lists, no silent fallback); `effort` in `none|low|medium|high` (xhigh/max rejected); `max_questions` int 1-3; `max_calls` int 1-2; `max_input_tokens`, `max_output_tokens`, `timeout_s` positive int; `budget_usd` number >0 and ≤1. GET `/api/settings` returns `"prompt_improver": {...all keys}`; PATCH body `{"prompt_improver": {"enabled": false}}` (partial) returns the full settings. Changes apply to the next unsent turn; read config per turn.

**UI** `frontend/src/components/PromptImprover.tsx`: `export function PromptImprover(props: { outcome: PromptImproverOutcome; card?: TaskCardView | null; itemId?: string | null; taskCode?: string | null; sessionId: string; onSaved?: (r: {task_code: string; task_link: string}) => void })`. Types: `PromptImproverOutcome = {status: "proceeded"|"asked"|"bypassed"|"unavailable"|"paused"; reason: string; questions_asked: number; calls: number; estimated_tokens: number; item_ids: string[]; task_code: string|null}`; `TaskCardView` = the TaskCard JSON. Renders: status line with reason text, goal, acceptance list, route chips, a "Save to Tasks" button (POST save; disabled with the code shown once `task_code` is set; error inline), a `*` hint when bypassed. Rendered from messages with `meta.notice=="prompt_improver"` (`meta.outcome`, `meta.item_id` = the card item for proceeded/asked, else null; `meta.failure_item_id` = the failure diagnostics item for unavailable/paused, else null; `ImproverOutcome.failure_item_id` carries the same id). Settings section "Prompt improver": enabled toggle (autosave), builtin/claude_code switches, model, effort (≤high), max questions 1-3, default-on text and the `*` hint.
